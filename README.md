# Wildberries Analytics Extension

Браузерное расширение (Chrome, Manifest V3) + локальный backend для аналитики
продаж на страницах поиска и карточек товаров Wildberries.

> ⚠️ **ДИСКЛЕЙМЕР (юридика).** Парсинг внутренних (недокументированных) API
> Wildberries нарушает их Пользовательское соглашение (ToS). Это учебный
> проект. Используя его, вы действуете **на свой страх и риск**. Автор не
> несёт ответственности за возможную блокировку аккаунта, убытки или любые
> иные последствия. Не используйте в производстве без понимания рисков.

---

## Состав

| Папка | Что внутри |
|---|---|
| `extension/` | Расширение Chrome MV3: `manifest.json`, `content.js`, `content.css`, `background.js`, `popup.html`, `popup.js`, `icons/` |
| `backend/` | Локальный сервер (Node.js, 0 npm-зависимостей): `server.js`, `db.js`, `parser/wb.js`, `start-server.bat`, `e2e_test.js`, `BACKEND.md` |

Backend использует **встроенный** модуль Node.js `node:sqlite` — `npm install`
**не требуется**. Нужен только Node.js 22+ (проверено на Node 24).

## 1. Backend (ваш ноутбук как временный сервер)

### Вариант A — одним кликом (Windows)
Откройте папку `backend` и запустите двойным щелчком:

```
backend\start-server.bat
```

Скрипт проверит версию Node.js и запустит сервер. Должно появиться:

```
[WBAnalytics][api] backend слушает http://127.0.0.1:4000
```

### Вариант B — вручную из терминала
```powershell
cd backend
node server.js
```

### Проверка, что сервер жив
Откройте в браузере: <http://127.0.0.1:4000/api/health>
Ожидаемый ответ: `{"ok":true,"service":"wb-analytics"}`

### Тесты backend (опционально)
```powershell
node e2e_test.js
```
Ожидаемо: `14 проверок ✓, 0 упало`.

### Остановить сервер
В окне, где он запущен, нажмите `Ctrl+C`. Либо:
```powershell
Get-NetTCPConnection -LocalPort 4000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

## 2. Расширение (установка в Chrome)

1. Распакуйте `wildberries-extension.zip` в любую папку (или используйте
   готовую папку `extension/`).
2. Откройте Chrome → `chrome://extensions`.
3. Сверху справа включите **Режим разработчика** (Developer mode).
4. Нажмите **«Загрузить распакованное расширение»** (Load unpacked) и выберите
   папку, где лежит `manifest.json` (папка `extension`).
5. Готово. Расширение активируется на страницах:
   - поиска/каталога — `https://www.wildberries.ru/catalog/*`
   - карточки — `https://www.wildberries.ru/catalog/*/detail.aspx`

## 3. Что делает расширение

- **На странице поиска** — рядом с карточкой товара появляется бейдж с
  расчётной выручкой в день (≈ X ₽/день).
- **На карточке товара** — панель WB Analytics **встраивается в интерфейс WB
  прямо под блоком цены, там где спец-предложения** (не висит поверх страницы):
  - артикул, цена, цена до скидки, рейтинг, отзывы, продавец;
  - скорость продаж, выручка в день/месяц (считает backend);
  - график изменения цены (Chart.js через CDN), когда накоплена история;
  - кнопка **«Отслеживать»** (сохраняет артикул в `chrome.storage.local`).
- **Popup** (клик по иконке расширения) — список последних товаров, топ-5 по
  скорости продаж и кнопка «Обновить сейчас».

### Откуда берутся данные карточки (важно)

`window.__INITIAL_STATE__` у WB больше не содержит данные карточки в прежнем
виде, а прямые запросы к `card.wb.ru` блокируются (403 + CSP WB запрещает
inline-скрипты и `chrome-extension://`). Поэтому парсер карточки (`content.js`)
работает по источникам с приоритетом:

1. **DOM карточки** (SSR-разметка WB: цена, рейтинг, отзывы, продавец) —
   основной и самый надёжный источник.
2. `window.__INITIAL_STATE__` (если WB снова начнёт его отдавать).
3. «Живое» дозаполнение: если рейтинг/отзывы/продавец догрузились позже,
   `MutationObserver` + опрос обновляют панель до ~40 секунд.

**Скорость продаж** считается backend'ом по **приросту отзывов** между
визитами (WB не показывает остатки на складе); пока замеров меньше двух,
показывается «зайдите на товар ещё раз позже». Отслеживаемые товары (кнопка
«Отслеживать») расширение дополнительно опрашивает в фоне раз в час через
`chrome.alarms` — фоновые вкладки, которые закрываются после парсинга.

> Весь UI расширения изолирован через **Shadow DOM**, поэтому стили
> Wildberries не ломаются.

## 4. Как это связано (архитектура)

```
Страница WB
   │  content.js парсит __INITIAL_STATE__ / DOM
   ▼
background.js (service worker)  ── обход CORS, throttling 1 req/сек,
   │                               ротация User-Agent/Referer, backoff при 429/403
   ▼
backend (node server.js)  ── SQLite (node:sqlite) ── метрики
   │
   ▼
content.js рисует UI (бейджи / панель) + popup.js
```

Расчётные метрики (скорость продаж по разнице остатков между парсингами,
динамика цены, выручка день/неделя/месяц) считает **backend** по истории
снапшотов.

## 5. Требования

- Node.js **22+** (для `node:sqlite`). Проверьте: `node -v`
- Chrome / Edge на базе Chromium (Manifest V3)
- Интернет-доступ к `*.wb.ru` и CDN Chart.js

---

## 6. Ограничения MVP

- Селекторы DOM привязаны к текущей вёрстке WB; при её изменении парсинг
  может потребовать обновления селекторов (в `content.js` есть фолбэки на
  `window.__INITIAL_STATE__`).
- Скорость продаж считается по видимым остаткам между парсингами одного
  артикула — чем чаще вы открываете карточку, тем точнее оценка.
